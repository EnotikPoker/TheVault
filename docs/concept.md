# Концепция The Vault

## Сканирование механизма

Основной режим — пространственная головоломка на основе Black Box. Правила лучей
заранее известны; игрок выясняет расположение элементов. На поле 6×6 скрыты
три элемента, по периметру находятся 24 порта.

Игрок запускает луч из порта и видит один из трёх исходов: поглощение, возврат
в тот же порт или выход в другой. Точный путь до вскрытия не показывается.
Клетки можно бесплатно помечать как предполагаемый элемент или пустое место;
все отметки сохраняются. После выбора трёх элементов проверяется весь набор.
Неверный ответ не раскрывает, какие клетки угаданы.

### Правила луча

1. Элемент непосредственно перед лучом поглощает его. Это правило имеет приоритет.
2. Один элемент впереди по диагонали отклоняет луч на 90° от элемента,
   до следующего шага. Элемент позади или сбоку без смещения вперёд не влияет.
3. Два элемента впереди по диагоналям разворачивают луч на 180°.
4. При отсутствии препятствий луч идёт прямо на одну клетку.
5. У входа сначала проверяется поглощение, затем диагональные элементы
   первой строки или столбца: они отражают луч до входа в поле.

Луч может несколько раз менять направление. Пара вход–выход работает в обе
стороны. Возврат может произойти как у края, так и после движения внутри поля;
игрок видит один результат «возврат». Исход не является готовым объяснением пути.
В инструкции над игрой есть учебный макет с видимыми элементами: можно запустить
пять подготовленных лучей и увидеть каждый случай с объяснением.

### Цель и оценка

Нужно найти три элемента с наименьшим количеством очков:

`очки = уникальные сканирования + 5 × неверные ответы`

Повторное сканирование известного порта и сканирование с обратного конца
записанной пары бесплатны. Отметки и время не добавляют очков. Правильный ответ
открывает сейф, фиксирует время и показывает настоящее расположение элементов.
В журнале можно выбрать проверенный луч и увидеть весь его путь.

Генератор исключает все раскладки, имеющие одинаковые результаты по всем портам
с другой раскладкой. Это позволяет однозначно найти решение через эксперименты.
Количество сканирований для решения не фиксировано, ограничения времени нет.

### Сейф дня и тренировка

Сейф дня один для всех, меняется в 00:00 по Москве. Прогресс у каждого игрока
отдельный. Начатую сессию можно закончить после смены даты; сегодняшняя создаётся
отдельно. Тренировки используют случайные раскладки. Замена незавершённой
тренировки с действиями требует подтверждения.

Прогресс сканера хранится в PostgreSQL и восстанавливается по ID сессии,
сохранённому браузером. Аккаунтов, рейтинга и ограничения числа сессий на человека
пока нет.

## Режим «Переключатели»

Первоначальная механика остаётся доступна в отдельной вкладке.
Инструкция объясняет четыре вида условий, чтение индикаторов и сравнение
результатов. Отдельный учебный сейф показывает пять проверок до открытия;
он не меняет текущую игру и не расходует попытки.

### Основная идея

Перед игроком виртуальный сейф с переключателями и индикаторами неизвестных систем.
Правила автоматически генерируются для каждого нового сейфа и остаются неизменными
на протяжении сессии. Игрок изучает их через эксперименты и открывает сейф,
стараясь потратить как можно меньше попыток.

Основа игры — выдвижение гипотез, контролируемые изменения и анализ обратной связи.
Для одного и того же сейфа одна комбинация всегда даёт один и тот же результат.

### Начальная панель

- Пять переключателей `S1`–`S5`, каждый в состоянии `ON` или `OFF`.
- Три индикатора: `POWER`, `SYNC`, `ACCESS`.
- Кнопка проверки комбинации.
- Счётчик попыток и время сессии.
- Журнал проверок для сравнения экспериментов.

Названия индикаторов не раскрывают условия их работы. До первой проверки
индикаторы имеют нейтральное состояние «не проверено».

Пример результата одной проверки:

```text
S1 = ON, S2 = OFF, S3 = ON, S4 = OFF, S5 = OFF

POWER   PASSED
SYNC    FAILED
ACCESS  PASSED

Attempts: 7
```

Этот пример иллюстрирует обратную связь, а не задаёт фиксированные правила.

### Игровой цикл

1. **Исследование.** Игрок осматривает панель нового сейфа. Скрытые правила
   не показываются; в будущем возможны подсказки и разные сложности.
2. **Эксперимент.** Игрок задаёт положения переключателей и нажимает проверку.
   Само переключение не расходует попытку.
3. **Анализ.** Каждая система независимо возвращает `PASSED` или `FAILED`.
   Каждая принятая сервером проверка увеличивает число попыток на один.
4. **Гипотеза.** Игрок предполагает связь, например равенство `S2` и `S4`,
   меняет комбинацию и сравнивает результат с предыдущими проверками.
5. **Вскрытие.** Если все системы прошли проверку в одной комбинации,
   сейф открывается. Игрок видит число попыток, время и объяснение каждого правила.

Отображаемые индикаторы относятся к последней проверенной комбинации.
Если переключатели изменились, интерфейс отмечает, что текущая комбинация ещё
не проверена. История сохраняет конкретную комбинацию вместе с её результатом.

### Правила и генерация

В первой версии ядра используются четыре вида правил:

- совпадение двух переключателей;
- различие двух переключателей;
- ровно `k` включённых в группе из 2–4 переключателей, где `k` — от 1 до размера
  группы минус один;
- чётное или нечётное число включённых в группе из 3–4 переключателей.

Все три правила должны выполняться одновременно. Типы правил игроку заранее
не сообщаются. Назначение правил индикаторам случайное: название системы
не указывает на проверяемое условие. Вложенных логических формул пока нет.

Генератор:

- оставляет ровно одну открывающую комбинацию;
- исключает константные индикаторы и правила с одинаковым поведением;
- проверяет, что удаление любого индикатора добавляет другие решения;
- вовлекает все пять переключателей в систему правил;
- допускает воспроизведение через seed.

Для решённого сейфа ядро выдаёт объяснение каждого правила и показывает
конкретные положения участвующих переключателей. Для неверной комбинации
объяснения недоступны.

Для пяти переключателей пространство содержит 32 комбинации. Его можно полностью
проверить при построении каталога. Само наличие единственного решения не гарантирует
интересную головоломку: оценка сложности и различимости правил требует игровых тестов.

Полностью исключить перебор при пяти бинарных переключателях невозможно.
Чтобы поощрять анализ, нужны информативные индикаторы, журнал экспериментов,
оценка по попыткам и постепенное усложнение связей. Лимиты попыток и штрафы
не входят в начальную концепцию.

### Завершение сессии

Сервер фиксирует время создания и открытия сессии. Время решения в первом MVP —
интервал между ними. После открытия комбинации больше не проверяются и число
попыток не меняется. Экран результата объясняет конкретные правила и показывает,
как последняя комбинация удовлетворяет каждому из них. Это помогает понять
решение даже при случайном успехе.
