# Архитектура

## Общая схема

```text
Браузер: React + TypeScript + Vite
          │ HTTP / JSON
          ▼
Go: transport/httpapi → session → vault
                          │
                          ▼
                   интерфейс хранилища
                          │
                          ▼
                  память процесса (MVP)
```

Реализованы игровое ядро `vault`, сессии, HTTP API и игровой интерфейс.
Frontend создаёт игры по действию игрока, восстанавливает их по ID и отображает
серверные результаты проверок.

## Backend

`cmd/server` отвечает за запуск, конфигурацию через окружение, таймауты
и корректное завершение по сигналам. `internal/transport/httpapi` переводит
HTTP-запросы в вызовы сценариев и сериализует ответы.

Пакет `internal/vault` хранит модель, вычисляет результат правил и генерирует сейфы.
Он не зависит от транспорта, базы данных и UI. Правила закрыты для изменения,
проверки не меняют сейф и допускают параллельные вызовы.

Интерфейс ядра:

- `Generate(seed int64) (Vault, error)` — сейф с единственным решением.
- `Vault.Check(Combination) CheckResult` — три индикатора и признак открытия.
- `Vault.Explain(Combination) ([3]Explanation, error)` — условия и фактические
  положения переключателей для решения; иначе `ErrVaultLocked` без объяснений.

`Combination` — массив из пяти `bool` в порядке S1–S5. Результаты содержат
идентификаторы `power`, `sync`, `access`. Нулевое значение `Vault` остаётся закрытым.
Ядро не считает попытки, не хранит время и не запоминает факт предыдущей проверки.

Генератор один раз строит каталог правил, сравнивает их поведение на всех
32 комбинациях и исключает дубликаты. Из троек правил отбираются только наборы
с одним решением, участием всех переключателей и необходимостью каждого индикатора.
Равновероятно выбирается одна допустимая тройка, затем перемешивается назначение
индикаторам. Каталог хранится в памяти процесса, генератор случайных чисел
создаётся отдельно для каждого вызова.

Одинаковый seed воспроизводит сейф при неизменной версии ядра. Совпадения между
разными seed допустимы. Seed служит для воспроизведения и не должен передаваться
игроку. Публичные HTTP-ответы собираются отдельно от модели `Vault`.

Пакет `internal/session` реализует создание сессии, проверку комбинации,
учёт попыток и времени, выдачу объяснений после открытия. Он определяет интерфейс
`Repository` и содержит реализацию `MemoryStore`. Сервер создаёт один экземпляр
хранилища и сервиса при запуске и передаёт сервис HTTP-обработчикам.

Сессия хранит неизменяемый сейф, время создания и открытия, историю проверок
и объяснения для решения. Число попыток равно длине истории. Каждая принятая
проверка добавляет запись, включая повтор той же комбинации. Для открытой сессии
проверки отклоняются, а прошедшее время больше не меняется.

`MemoryStore` защищает операции одним mutex. `Update` работает с копией сессии
под блокировкой: сохраняет её при успехе и отбрасывает при ошибке. Чтение и запись
копируют историю, время открытия и объяснения, чтобы вызывающий код не получил
ссылки на изменяемые данные хранилища. Проверки и чтение возвращают публичный
`Snapshot`, в котором нет модели сейфа.

Сервис использует `crypto/rand` для ID сессии и seed генератора. Часы и функции
создания ID и сейфа можно подменить через `Options` для детерминированных тестов.

Сервер — источник истины для правил, результатов, числа попыток и времени.
HTTP DTO отделены от внутренней модели. В ответах нет seed и объекта сейфа;
объяснения условий появляются только после открытия. До первой проверки
последняя комбинация и значения индикаторов равны `null`.

## Frontend

`src/main.tsx` монтирует React-приложение в `StrictMode`. `App` содержит заголовок
и игровой экран `VaultGame`. Хук `useVaultGame` управляет серверным снимком,
редактируемой комбинацией, запросами и восстановлением. `VaultPanel`, `VaultHistory`
и `VaultResult` получают данные и обработчики через props. Redux и маршрутизатор
не используются.

`src/shared/api/vaults.ts` содержит типы ответов, проверку структуры JSON
и клиент трёх игровых методов. Запросы имеют тайм-аут 5 секунд и поддерживают
отмену. Новая сессия создаётся обработчиком кнопки, а не эффектом.

UI хранит редактируемую комбинацию отдельно от последней проверенной. Индикаторы
всегда относятся к серверной проверке; при изменении переключателей появляется
соответствующая подпись. Журнал показывает новые попытки первыми. Возврат
комбинации из журнала меняет только локальный выбор.

На время запроса игровые действия блокируются. Дополнительно хук защищает
от двойного нажатия, отменяет запросы при размонтировании и игнорирует устаревшие
ответы. Счётчик и история обновляются только из ответа сервера.

В `localStorage` хранится только ID под ключом `the-vault.session-id`. После
открытия страницы выполняется `GET` сохранённой сессии. `404` удаляет ID
и возвращает стартовый экран; временная ошибка сохраняет ID и позволяет повторить
загрузку. Недоступное хранилище не мешает играть в текущей вкладке. При создании
нового сейфа ID заменяется только после успеха запроса.

После ошибки проверки приложение запрашивает состояние через `GET`, не повторяя
`POST`: сервер мог уже принять попытку. Пока состояние неизвестно, новые проверки
заблокированы. После восстановления редактируемая комбинация сохраняется;
для открытого сейфа панель показывает выигрышную комбинацию сервера.

Таймер дополняет серверный `elapsedMs` локальным временем через `performance.now()`
и обновляет показания раз в секунду. После открытия отображается фиксированное
серверное время. Переключатели и возврат комбинаций из журнала блокируются,
результат и объяснения остаются доступны для просмотра.

Интерфейс описан React-компонентами на TypeScript (`.tsx`). Vite использует
официальный React-плагин для разработки с Fast Refresh и сборки.
Зависимости зафиксированы в lock-файле.

Frontend-тесты используют Vitest, jsdom и React Testing Library. Важные сценарии
проверяются через действия пользователя; время и HTTP-ответы подменяются.
Общая команда `make test` запускает тесты Go и frontend.

## Хранение и запуск

Хранилище работает в памяти одного процесса: перезапуск сервера сбрасывает
сессии. Срока хранения и автоматического удаления пока нет.
Постоянное хранение и авторизация добавляются при появлении требований
к восстановлению прогресса, аккаунтам или таблице результатов.

В разработке Vite проксирует `/api` на Go. Production-раздача статических файлов
и reverse proxy будут настроены отдельным этапом. Docker, база данных и очереди
не требуются для текущего каркаса.
