# HTTP API

Базовый путь: `/api`. Формат успешных ответов: JSON.

## Реализовано

### `GET /api/health`

Проверка доступности процесса. Ответ `200 OK`:

```json
{"status":"ok"}
```

Это проверка HTTP-сервера; зависимых сервисов в текущем каркасе нет.

## Запланировано для MVP

Ниже — проект контракта, эти маршруты ещё не реализованы.
Публичные идентификаторы сессий должны быть непредсказуемыми.

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/v1/vaults` | Создать сессию с новым сейфом |
| `GET /api/v1/vaults/{id}` | Получить публичное состояние сессии |
| `POST /api/v1/vaults/{id}/checks` | Проверить комбинацию |

Создание возвращает `201 Created` и публичное состояние: идентификатор,
перечень переключателей и систем, ноль попыток, статус `locked`, время начала.
Правила и seed генератора не возвращаются.

Тело запроса проверки содержит все пять значений в порядке `S1`–`S5`:

```json
{"switches":[true,false,true,false,false]}
```

Сервер проверяет типы и длину массива до изменения сессии. Корректная проверка
возвращает `200 OK`, например:

```json
{
  "id": "session-id",
  "switches": [true, false, true, false, false],
  "indicators": [
    {"id": "power", "passed": true},
    {"id": "sync", "passed": false},
    {"id": "access", "passed": true}
  ],
  "attempts": 7,
  "status": "locked",
  "elapsedMs": 42000
}
```

При открытии `status` становится `opened`, время фиксируется, в ответ добавляются
объяснения правил. До этого поле объяснений отсутствует. Повторная принятая
проверка той же комбинации расходует новую попытку; кнопка на клиенте блокируется
на время запроса. Автоматические повторы `POST` без защиты от дублей не допускаются.

Запланированные ошибки: `400` — некорректный запрос, `404` — сессия не найдена,
`409` — сейф уже открыт. Ошибки не расходуют попытки. Единый JSON-формат ошибок
будет введён вместе с игровыми маршрутами; текущие `404`/`405` формирует `net/http`.
